YOder 是一款基于 PySide6 与 QWebEngineView 构建的桌面端 AI 编程助手，深度整合了多平台大模型对话、文件树管理、智能记忆概括以及基于 TaskChunks 算法的 Agent 思维链模式，旨在为开发者提供高效、智能的代码编写与工程辅助体验。

## 核心功能

**AI 对话**
- 支持阿里、DeepSeek、智谱、Kimi 等多平台大模型接入。
- 支持自定义模型名称，提供流式输出与思考过程展示。
- 完整支持 Markdown 渲染、KaTeX 数学公式、代码语法高亮及代码块一键复制。

**文件与界面**
- 支持加载本地文件夹并以树形结构展示，自动过滤无关目录。
- 支持多文件夹同时管理，可直接发送图片、PDF、Word 及文本文件。
- 采用三栏布局（对话列表、聊天区、文件树），所有分隔条均支持拖拽调整。
- 支持自定义全局或对话级壁纸。

**对话与记忆管理**
- 支持对话的新建、重命名与删除，支持删除单轮对话与重新生成。
- 每个对话可独立绑定专属的模型配置与系统提示词。
- 具备记忆概括机制，当对话轮数或 Token 超出限制时，自动在后台进行概括，不阻塞当前操作。

## TaskChunks 算法详解

TaskChunks 算法是一种专为长文本生成与复杂工程任务设计的 Agent 思维链编排机制。该算法将庞大的生成任务解耦为结构化的四阶段管线，通过状态持久化与局部重试机制，有效解决大模型在处理复杂任务时面临的上下文丢失、任务拆解困难以及长文本输出格式崩溃等核心痛点，确保生成过程的稳定性与最终输出的高质量。

### 核心四阶段管线

#### 阶段一：文件读取与框架构建

- **信息校验与 Stop 机制**：系统首先读取用户选中的文件列表与内容预览。若判定关键信息缺失（如：用户指令意图模糊、缺少核心业务逻辑代码、未提供必要的配置文件或上下文依赖等），算法会触发 Stop 机制。此时，Agent 会主动向用户发起提问以澄清需求或请求补充文件，并暂停当前管线。待用户补充信息后管线重启，从而避免在信息不足时的无效生成与资源浪费。
- **输出框架构建**：信息充足后，大模型根据完整文件内容与用户指令，自主设计最终输出的骨架结构。该结构由固定的说明文本与 `[task_n]` 占位符交织而成。在生成文本框架的同时，系统会同步生成一份结构化的任务清单，详细定义每个 `[task_n]` 占位符的生成目标、关联的源文件列表以及验收标准。这种设计将庞大的长文本生成任务降维为多个独立的短文本生成子任务，为后续阶段的内容填充提供精确指引。

#### 阶段二：逐 Task 内容填充与动态拆分

- **输出格式预设机制**：系统在填充每个任务前，会根据任务关联的文件类型自动选择对应的输出格式预设。预设作为系统提示词的一部分被注入，强制约束 AI 的输出格式（如唯一性、完整性、无代码块包裹等），有效防止多版本输出、思考泄露等问题。
- **独立上下文注入**：系统遍历任务清单，逐个处理处于待处理状态的任务。在填充每个任务时，仅注入该任务专属的关联文件与框架上下文片段，确保大模型注意力高度集中，避免全局上下文超限。
- **子任务动态拆分**：在填充过程中，若大模型评估当前任务过于复杂，可触发动态拆分机制。系统会自动解析拆分指令，在运行时创建子任务（如将 `task1` 拆分为 `task1_1` 与 `task1_2`），并无缝将其纳入后续填充队列，实现任务粒度的自适应调整。

**支持的输出格式预设**

| 类别 | 预设名 | 适用场景 |
|------|--------|----------|
| 编程语言 | `python`, `c`, `cpp`, `java`, `javascript`, `sql`, `code` | 各类源代码文件 |
| 前端文件 | `html`, `css` | Web 前端开发 |
| 脚本文件 | `shell`, `batch` | 系统脚本 |
| 配置文件 | `yaml`, `json` | 配置文件 |
| 文档文本 | `markdown`, `plaintext`, `article` | 文档、报告、文章 |
| 对话创作 | `roleplay`, `dialogue` | 角色扮演、问答对话 |
| 数据结构 | `csv`, `structured` | 数据文件、结构化 JSON |
| 通用 | `mixed` | 代码与文字混合内容 |

#### 阶段三：完整格式与内容审查及自动重做

- **全局一致性审查**：所有任务填充完毕后，系统对拼接后的完整输出进行全局审查，校验用户指令执行度、格式连贯性及代码可用性。
- **局部自动重做**：若审查发现特定任务存在缺陷，系统不会推翻全局结果，而是精准定位失败的任务节点，注入审查反馈，并将其状态重置。随后管线局部回退至阶段二，仅对失败任务进行定向重做。该机制最多循环 6 次，以最小代价修复局部错误。

#### 阶段四：最终输出

- **占位符替换与全局组装**：当全局审查确认所有任务节点均通过验收后，系统遍历初始框架构建阶段生成的骨架文本，将所有 `[task_n]` 占位符精准替换为阶段二中填充的实际内容，完成最终完整文本的组装。
- **流式分块推送**：为保障前端渲染性能并提供平滑的用户体验，系统将组装完毕的长文本进行合理分块，通过流式接口逐块输出给用户。该过程模拟了常规的打字机效果，在避免长文本一次性渲染导致界面卡顿的同时，标志着整个 Agent 思维链编排流程的圆满结束。

### 状态管理与核心机制

- **`[task_n]` 占位符机制**：作为文本框架中的结构锚点，将单一的长文本生成任务降维为多个独立的短文本生成子任务。这不仅大幅降低了单次生成的 Token 压力，还通过物理隔离有效防止了长文本生成中常见的逻辑偏移与格式崩溃。
- **`output.json` 全局状态中心**：作为整个管线的数据枢纽，持久化存储框架文本、任务依赖树、执行状态（待处理/已完成/错误）以及审查反馈。它确保了在阶段流转、子任务动态创建、局部重做甚至进程意外中断时，系统能够精确恢复上下文并继续推进，提供了极高的鲁棒性。

## 菜单与操作说明

| 按钮/操作 | 位置 | 功能 |
|---|---|---|
| [设置] | 输入框左下角 | 全局设置（平台、API Key、模型、思考强度、记忆轮数、Max Tokens） |
| [记忆] | 输入框左下角 | 记忆概括设置（开关、概括轮次、字数、合并段数） |
| [思维链] | 输入框左下角 | 开启/关闭 Agent 思维链模式 |
| [关闭] | 右上角 | 关闭右侧文件栏 |
| [刷新]/[移除] | 右侧路径栏 | 刷新或移除当前文件夹 |
| [新建对话] | 左侧底部 | 创建新对话 |
| [重命名]/[删除] | 对话列表悬停 | 重命名或删除对话 |
| [删除] | 用户消息左下角 | 删除该轮对话 |
| [重新生成] | AI 回复右上角 | 重新生成该回复（Agent 模式下可选择转换模式或重跑四阶段） |
| [全选]/[清空] | 右侧顶部 | 全选或取消全选文件 |
| [加载] | 文件夹路径旁 | 加载指定文件夹 |

> 提示：在输入框空白处连续点击发送按钮 5 次可打开壁纸设置。

## 配置与运行

- 全局配置保存在 `config/info.json`。
- 对话级配置（模型、记忆、壁纸、Agent 状态等）保存在 `records/<对话文件夹>/` 下。

```bash
pip install -r requirements.txt
python run.py
```
